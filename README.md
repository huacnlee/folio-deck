# gpui-shell benchs

A collection of [gpui-shell](https://gpui-kit.com/shell/) applications generated from scratch by AI coding agents. They exist to measure two things:

1. **AI friendliness** — given only a design or a brief, plus the `AGENTS.md` and `gpui-kit.d.ts` that gpui-shell generates, how quickly and cheaply can an agent produce a working native application?
2. **Capability** — can the gpui-shell runtime (layout, painting, input, files, network, storage, processes…) carry a genuinely useful application, not just a static screen?

Every application is a self-contained gpui-shell application directory:

Install the latest runtime from Git (requires Rust/Cargo and the platform's GPUI build dependencies):

```bash
cargo install --git https://github.com/longbridge/gpui-kit gpui-shell --locked
```

Then run an application:

```bash
gpui-shell types -d apps/<name>          # write gpui-kit.d.ts (not committed)
gpui-shell check -d apps/<name>          # load, render and materialize once
gpui-shell dev apps/<name>               # run it, reloading on save
```

## Applications

| Application | What it does |
| --- | --- |
| [folio-deck](apps/folio-deck) | Folio Desk, a Gmail desktop client: OAuth sign-in, local cache, drafts, replies, one-command installer and a macOS `.app` |
| [tendra](apps/tendra) | Tendra, a bid pipeline board: drag cards between stages, details drawer, persisted changes |
| [ocean-view](apps/ocean-view) | OceanView, live fleet tracking: great-circle dead reckoning, sea-lane routing, ETA, fuel burn, rule-based alerts, report export, draggable and zoomable map |
| [signed](apps/signed) | Signed, a PDF signer: opens real PDFs with a pure-JS parser, keeps a drawn/typed signature library, saves signed copies by incremental update |
| [skills-manager](apps/skills-manager) | Skills, an agent skills manager: scans, enables, disables, trashes and restores local skills; installs new ones from GitHub |
| [finder](apps/finder) | Finder, an Omarchy-style file browser (first built as Omanta): real folders, tabs, resizable split view, preview pane, right-click menus, pinned Places, copy/move, recoverable trash and undo |
| [disktree](apps/disktree) | Disk usage treemap: real allocated/apparent sizes, file/age metrics, drill-down, cleanup review and recoverable trash |
| [chat](apps/chat) | Chat, a ChatGPT / Claude Desktop-style client for the local `claude` and `codex` CLIs: saved, searchable chats, resumed sessions, Markdown replies, provider and model switching |

```text
AGENTS.md                generated by gpui-shell 0.7.3 for every app; regenerate after upgrading, never edit
scripts/session-stats.py time and token usage from Claude Code / Codex transcripts
apps/<name>/             one gpui-shell application per directory
```

## Releases

Pushing a semantic-version tag such as `v0.2.0` runs `.github/workflows/release.yml`. It tests the applications, builds one `<app>-<tag>.tar.gz` per directory with a manifest under `apps/`, checks the unpacked applications with the latest gpui-shell Git build, and publishes every archive plus `SHA256SUMS` in one GitHub Release. Tags such as `v0.2.0-beta.1` produce prereleases. Each packaged manifest uses the tag's version; source manifests remain unchanged.

The archives contain JavaScript, manifests, assets, documentation and the license. **No gpui-shell binary is included.** Install the runtime with the Cargo command above, then extract an app into `~/.gpui-shell/apps`:

```bash
mkdir -p ~/.gpui-shell/apps
tar -xzf skills-manager-v0.2.0.tar.gz -C ~/.gpui-shell/apps
gpui-shell run skills-manager
```

Preview all release packages locally:

```bash
python3 scripts/package-apps.py --tag v0.2.0 --out dist
```

## Rules

A new application only counts if it follows these rules.

### 1. Real functionality

An application must actually do what it claims; recreating the screen is only the starting point.

- Data comes from a real source (local files, a network API, system facilities) or a real calculation, not numbers fixed in the interface. Where sample data is unavoidable, the README says which parts are simulated and why.
- The main actions have real effects: saving writes to disk or storage and survives a restart, exporting produces a file other software can open, edits change the real objects.
- Loading, empty, failure and retry states exist. Destructive actions ask for confirmation and are undoable where possible.
- Pure logic (parsing, calculation, file formats) lives in separate modules covered by `node --test`. Tests run with only the globals gpui-shell provides, and neither tests nor `check` may touch the user's real data.

### 2. gpui-shell only

- Use only the built-in modules listed in `AGENTS.md` (`gpui-kit`, `gpui-base`, `gpui-component`, `gpui-fps`) and relative modules: no npm packages, no DOM or Web APIs.
- `gpui-kit.d.ts` from `gpui-shell types` is the API reference; do not commit it.
- `gpui-shell.json` asks for the narrowest grants (`fs`, `network`, `clipboard`, `process`), and the app README explains each one.

### 3. Layout and documentation

- Each application lives in `apps/<kebab-name>/` and runs directly with `gpui-shell run -d`. Its `id` is `com.huacnlee.<name>` and stays stable.
- Each application has a `README.md`: what it is, a *Reference* section crediting the original design or software with a link, how to run it, features and shortcuts, permissions, differences from the original and known limits.
- `gpui-shell check -d apps/<name>` and the application's tests pass before committing; behavioural changes are also checked in a running window.

### 4. Record the cost

- Build from zero to done in **one session** where possible, note the start time, and keep the transcript.
- When done, run `scripts/session-stats.py` and add the results to the tables above (wall, active, prompts, tokens, model), with anything unusual in the notes (interruptions, several sessions, manual edits).

## Measuring

```bash
# Claude Code: ~/.claude/projects/<escaped path>/<session>.jsonl
# subagents:   ~/.claude/projects/<escaped path>/<session>/subagents/agent-*.jsonl
python3 scripts/session-stats.py ~/.claude/projects/-Users-me-work-app/<session>.jsonl

# Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl
python3 scripts/session-stats.py ~/.codex/sessions/2026/10/13/rollout-*.jsonl

# Sum several sessions, or cut out a time range
python3 scripts/session-stats.py a.jsonl b.jsonl --from 2026-10-13T06:00:00Z --to 2026-10-13T08:00:00Z
```

- Claude Code: per-call `usage` is summed after de-duplicating by message `id` (a streamed message is written on several lines).
- Codex: the cumulative usage of the last `token_count` event; `cached_input_tokens` counts as cache reads, the rest of the input as uncached input, and `reasoning_output_tokens` is already part of the output.
- Prompts are messages written by a person (including messages that only contain a screenshot), not tool results or injected system content. In Claude Code that includes messages sent while the agent was working (queued commands), and excludes hook feedback, interruption notices, the summary that continues a compacted session, and images read back by tools. A `/goal` request is not a user message in the transcript; add it by hand.
